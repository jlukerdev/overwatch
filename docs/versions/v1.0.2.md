## Revisions to existing requirements

### Screen Settings bars (CAM-1, QUAL-1, DOOR-7, DOOR-9)
- The shared Settings bar (`ui/SettingsBar`) moves from the bottom of the screen to the **top**: directly under the screen's header, full width and flush with the screen's sides, **collapsed by default** each time the screen opens. Opening it **expands downwards over the screen's content**, covering it rather than moving it, as the bottom bar does today; the collapsed bar takes its own row, so nothing is hidden while it is closed. If the open bar is taller than the space below the header, it scrolls inside itself. The gear icon, title and chevron, and everything inside the bar, are unchanged.
- Order on the screen: header, then the Settings bar, then any banner (the Doors screen's stale-list and emergency banners), then the content.
- Applies to the Cameras screen (QUAL-1 stream defaults) and the Doors screen (DOOR-9 polling), and to the Streams screen in RTSP mode (RTSP-1), which uses the same bar.

### View editor (VIEW-3)
- **Display and Quality start collapsed** each time the editor opens (they started expanded in v1.0.1). Each still opens with its own toggle, and the choice is still not stored.
- **Cell actions move into the Cell pane.** The selection toolbar above the canvas is removed. **Merge**, **Split** and **Clear cameras** sit at the top of the Cell tab as one row of three equal-width, full-height buttons (the standard `.button`, not `--sm`) with the icon over the label, which makes them taller than a standard button so "Clear cameras" fits the panel (user decision 2026-11-20). After an action disables its own button, keyboard focus moves to the next action that can still act. Merge and Split use the default style and Clear cameras the danger style. A button that cannot act is disabled and says why in its tooltip, as today. Above the row, a caption gives the selection: "1 cell selected" / "N cells selected".
- Under the actions: the inspector for the selected cell when exactly one is selected. With several selected: "Select one cell to edit its cameras and settings." With none: "Select a cell on the canvas to edit it.", with the actions disabled.
- **Selecting shows the Cell pane.** Every change to a non-empty selection (click, drag, shift-click) switches the side panel to the Cell tab, even if the View tab was showing. The user can still switch back to the View tab; it stays there until the selection changes again. Clearing the selection (`Esc`) leaves the tab as it is.

## Requirements this version adds

### App mode (MODE)
- **MODE-1** The app runs in one of two modes, saved in `config.json` as `mode`: **UniFi Protect** (`protect`, the default, which is the app as it is today) or **RTSP streams** (`rtsp`). An existing install loads as `protect`, so nothing changes for it.
- **MODE-2** Settings opens with the mode choice, as its most prominent element: two large selectable cards side by side (stacked at narrow widths), each with an icon, a title and one line — **UniFi Protect** ("Cameras, motion events and doors from your UniFi console") and **RTSP streams** ("Any camera with an RTSP address. No UniFi console needed."). The selected card has the accent border and a check mark. It is a radio group: arrow keys move between cards and it has a visible focus ring. Choosing the other card asks first in a `ConfirmDialog` ("Switch to RTSP streams?" — "Live video stops and the UniFi connection closes. Your UniFi settings, Views and door links are kept for when you switch back.", confirm button "Switch to RTSP streams"). The switch is saved at once; there is no separate Save.
- **MODE-3** What each mode shows:
  - **Protect:** unchanged from v1.0.1.
  - **RTSP:** Settings shows only the mode cards, then one line pointing to the Streams screen with an **Open Streams** button. Every UniFi setting is hidden: console address, API key, Access switch, token and URL, certificates, Test connection and Connect. The header nav is **Streams** and **Live**; Cameras and Doors are hidden, and so are the Protect and Access connection badges. The start screen is Live when there is at least one RTSP View and one stream, otherwise Streams. A first run is still in Protect mode and still opens on Settings with no console address, where the mode cards are the first thing the user sees.
- **MODE-4** **In RTSP mode the app makes no Protect or Access call of any kind**: no REST, no WebSocket, no door polling, no launch connect. Switching to RTSP closes the Protect feeds and the door-state monitor, drops the inventory and unregisters every go2rtc stream. Switching back to Protect behaves like a launch: it connects on its own only when CON-4's launch rule allows it, otherwise the user presses Connect. Stored UniFi settings, secrets, certificates and door links are never cleared by a switch.
  - **Views are kept per mode.** Each mode has its own Views and its own last View. The renderer is shown the active mode's Views as `views` / `lastViewId`, so the View switcher, editor and grid work unchanged, and `vp:views/set` / `vp:views/active` write to the active mode's list. A mode's Views never show the other mode's cameras.

### RTSP streams (RTSP)
- **RTSP-1** **Streams screen** (RTSP mode only), where the RTSP feeds are configured. Header: "N streams" and **Add stream**. Each stream is a card with a camera icon (no thumbnails in v1.0.2), its name, the HIGH / MED / LOW chips showing which qualities have a URL (the QUAL-7 chip style, missing ones dimmed), **Edit** and **Delete**. Streams are listed in name order. With no streams the screen is an empty state: "No streams yet — Add a stream for each camera, using its RTSP address." with **Add stream**. The QUAL-1 default-quality Settings bar sits at the top of this screen in RTSP mode, as it does on the Cameras screen in Protect mode (see the Settings bar revision above).
  - **Add / Edit** is a dialog: **Camera name** (required, 1–64 characters, unique ignoring case) and three URL fields, **High**, **Medium** and **Low** quality, each with one line of help. **At least one URL is required.** Save is enabled only when the form is valid; errors show under their field.
  - **Delete** asks first ("Delete "<name>"?" — "Views that show this stream will show Camera not found.", confirm button "Delete stream") and removes the stream and its URLs. Cells that showed it are drawn as "Camera not found" (VIEW-4), like a camera that left the console; Views are never edited for the user.
- **RTSP-2** **Stream URLs are secrets and write-only** (CON-2). They are stored encrypted in `secrets.bin`, never in `config.json`, never logged (NFR-9's redactor already covers whole RTSP(S) URLs) and never sent back to the renderer: the renderer only learns which qualities have one, as booleans. When editing, a quality with a URL shows a "Saved" chip and a **Replace** button (opens an empty field) and **Clear**. An untouched quality keeps its URL. Clearing the last remaining URL is refused, since a stream needs at least one.
  - **Validation**, in the dialog and again in main: `rtsp://` or `rtsps://` only, with a host, at most 2048 characters, no whitespace or control characters. Every other scheme is refused, because go2rtc treats some source schemes (`exec:`, `ffmpeg:`, …) as commands to run.
  - Config holds `rtsp: { streams: [{ id, name }], views, lastViewId }`. A stream id is `rtsp-<uuid>`, URL-safe and never confused with a Protect camera id. Secrets hold `rtspUrls: { "<streamId>": { high?, medium?, low? } }`. No `schemaVersion` bump: absent blocks load empty.
- **RTSP-3** **Playback.** In RTSP mode main's camera inventory is built from the configured streams (name; model "RTSP stream"; always `CONNECTED`, because RTSP has no presence feed and a stream that cannot connect shows "Stream could not start"). Main pushes it as `cameras` after every change. `ensureStream(id, quality)` reads the URL from the secrets and registers it in go2rtc. `rtsps://` becomes go2rtc's `rtspx://` (no certificate verification, see RTSP-5); `rtsp://` is passed as is.
  - **Quality fallback.** QUAL-1…5 apply unchanged. When the quality asked for has no URL, the closest one that has a URL is played, preferring the lower on a tie: low → medium → high, medium → low → high, high → medium → low. The stream handle names the quality actually served, so the picker's colour and the badge show what really plays (QUAL-7). In the quality pickers a quality with no URL is listed but disabled, marked "(not set)".
- **RTSP-4** **Live and the View editor in RTSP mode.**
  - There are no motion, smart-detection or ring events. In the cell inspector, Rotate works and **Switch on events** is hidden; the stored event settings are kept but unused.
  - No unlock button and no Doors (MODE-3).
  - No snapshots: the View editor's palette and cells and the connecting placeholder use the camera icon (no blurred still).
  - **Audio:** the mute toggle shows once the playing stream turns out to carry an audio track (the audio codec in go2rtc's MSE handshake), not from camera flags. AUD-1…3 apply otherwise.
  - "Create a View" uses the streams in name order (VIEW-4).
  - The perf harness runs in Protect mode only.
- **RTSP-5** **Security of user-entered sources.** In Protect mode a source must point at the pinned console host (R4). In RTSP mode main instead registers **only** URLs it reads from its own secrets, validated by RTSP-2's rules. The renderer names a stream id and a quality, never a URL. `rtsps://` streams are not certificate-checked (go2rtc cannot pin), which is a new risk to add to SPEC §7 as R12: accepted, because the cameras are on the LAN and plain `rtsp://` is unencrypted anyway. go2rtc stays loopback-only with its per-launch credentials (§5.3).

## Feature details

### F1.0.2-1 — Settings bars at the top

### F1.0.2-3 — App mode foundation
Main and shared code only, plus tests. No visible UI change in Protect mode.
- `src/shared/models.ts`: `mode` and the `rtsp` block in `SettingsSchema` (defaults so old files load unchanged).
- `src/main/secrets/secrets.ts`: `rtspUrls` stored encrypted; the renderer gets per-stream, per-quality booleans in `SecretsStored`.
- Per-mode Views (MODE-4): main shows the renderer the active mode's Views and routes `vp:views/*` writes to them.
- `vp:app/mode` IPC (zod-validated): saves the mode, then tears down or restores the Protect side (connection manager, door-state monitor, go2rtc streams) and answers with `AppState`.
- Unit tests: config load and defaults, secrets round trip, View routing per mode, and that RTSP mode makes no Protect or Access call (fake clients record zero requests).

### F1.0.2-4 — Mode picker and mode-aware shell
- Settings: the MODE-2 cards at the top. New shared styles go in `styles.css` / `ui/` (tokens only, focus ring, reduced motion), and the switch uses `ConfirmDialog`.
- RTSP mode hides every UniFi setting and shows the Open Streams line (MODE-3).
- Header: mode-aware nav (Streams + Live, or Cameras + Doors + Live) and badges. Keep "Cameras", "Doors", "Live" text unchanged for the perf harness.
- `initialScreen`: the RTSP start-screen rule, with tests.
- The Streams screen can be a placeholder until F1.0.2-5.

### F1.0.2-5 — Streams screen
- `vp:rtsp/streams/save` (create or edit: id optional, name, and per quality a URL to set, `null` to clear, or absent to keep) and `vp:rtsp/streams/delete`, both validated in main (RTSP-2) and answering `AppState`.
- `features/streams/`: card list, empty state, Add/Edit dialog with write-only URL fields, delete confirmation, QUAL-1 Settings bar.
- Tests: form validation, the "at least one URL" rule, name uniqueness, URLs never present in any IPC reply.

### F1.0.2-6 — RTSP playback
- Inventory from the streams in RTSP mode, pushed as `cameras`.
- An RTSP branch in the stream registry: URL from the secrets, quality fallback (pure function in `src/shared/quality.ts`, unit-tested), `rtsps`→`rtspx` transform, the handle reporting the served quality. A changed or cleared URL invalidates that stream's registration.
- go2rtc manager: in RTSP mode, accept sources from the registry's validated list instead of the pinned-host check (RTSP-5).
- Quality pickers: unset qualities disabled, "(not set)".
- Check on screen against a real RTSP camera (a Protect camera's own RTSP URL works for this).

### F1.0.2-7 — Live and editor in RTSP mode
- Hide Switch on events in the inspector; no unlock; icon in place of snapshots in the palette, cells and connecting placeholder.
- Audio detection from the MSE handshake's codecs, feeding the audio store's "has audio" in place of the mic flags.
- "Create a View" from the streams in name order.

## Decisions

- Views are separate per mode.
- Stream URLs are write-only once saved.
- The mute toggle in RTSP mode shows when the stream carries audio.
- No thumbnails for RTSP streams in v1.0.2: icon only.
- Access and doors are unavailable in RTSP mode (they are UniFi features).
- The Settings bar at the top covers the content when open; it does not push it down.
- Display and Quality start collapsed every time; still not remembered.
- Selecting a cell always switches to the Cell pane; the View tab stays reachable until the selection changes.
